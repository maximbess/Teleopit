# Предпросмотр эталонных движений на лестнице

Окно MuJoCo показывает робота, движущегося по результату обратной кинематики,
заданные траектории частей тела и текущие ошибки относительно целей.
Это **кинематический предпросмотр**, без исполнения приводами и без обучения.
Weld-связи отключены: опоры удерживаются задачами IK, а не физическими силами.

## Запуск

Из корня проекта в PowerShell:

```powershell
.\scripts\render\preview_ladder_reference.ps1
```

Либо в окружении с зависимостями проекта:

```shell
python scripts/render/preview_ladder_reference.py
```

Первые секунды занимает вычисление движения, затем открывается окно.
По умолчанию воспроизведение идёт с половинной скоростью и останавливается в конце.
Мышью можно вращать и приближать камеру штатными средствами MuJoCo.

| Клавиша | Действие |
|---|---|
| P | Пауза / продолжить |
| J / L | Предыдущий / следующий кадр с остановкой |
| R | Вернуться к началу; если стояла пауза, нажать P |
| [ / ] | Уменьшить / увеличить скорость |
| T | Показать / скрыть пути |
| C | Вернуть начальную камеру |

Оранжевая дорожка — левая кисть, голубая — правая, зелёная и жёлтая — стопы,
фиолетовая — таз, розовая — корпус. Цветные точки обозначают цели.
Красный отрезок показывает расхождение между фактическим положением и целью
более 5 мм. В тексте окна указаны текущие позиционные и угловые ошибки.

## Два варианта первой перестановки

По умолчанию загружается `assets/motions/ladder_first_hand.json`:

- исходная поза взята из общих с обучением определений сцены;
- обе руки начинают на перекладине 5, стопы остаются на перекладине 2;
- перед переносом кисти таз и корпус смещаются на 2 см к лестнице и на 1 см вверх;
- кисть отходит на 10 см, поднимается на шаг лестницы и подходит к перекладине 6;
- правая кисть и обе стопы сохраняют исходные позиции и ориентации;
- длительность 4.4 с при 50 Гц.

При проверке исходного эскиза обнаружились недостаточная досягаемость конечной
точки и пересечение кисти с перекладиной. Поэтому предпросмотр по умолчанию
использует уточнённый вариант выше. Исходный эскиз сохранён отдельно:

```shell
python scripts/render/preview_ladder_reference.py --reference assets/motions/ladder_first_hand_original.json
```

Первоначальные материалы в `outputs/ladder_analysis/first_hand_reference`
описывают исходный эскиз и не заменены новым вариантом.

## Дорожки для других частей тела

В одном JSON можно задавать сколько угодно `tracks`. Каждая дорожка привязана к
существующему `site` либо `body` модели и имеет независимые ключевые кадры.
Обе руки, стопы, таз и корпус уже заведены отдельными дорожками.
Решение IK учитывает их одновременно; если цели противоречат друг другу,
ошибки остаются видимыми и сохраняются в отчёте.

Пример структуры дорожки (координаты только для иллюстрации формата):

```json
{
  "name": "left_foot",
  "kind": "site",
  "target": "left_foot",
  "color": [0.25, 0.9, 0.45, 1.0],
  "position_weight": 5.0,
  "orientation_weight": 0.5,
  "keyframes": [
    {"time_s": 0, "offset_m": [0, 0, 0]},
    {"time_s": 2, "offset_m": [0, 0, 0]},
    {"time_s": 3, "offset_m": [-0.05, 0, 0.15]},
    {"time_s": 4, "offset_m": [0.105, 0, 0.28]}
  ]
}
```

- `offset_m` — смещение от **начальной мировой позиции** этой части тела,
  а не от предыдущего ключевого кадра и не в локальных осях тела.
- Вместо него можно указать абсолютную мировую `position_m`.
- `quaternion_wxyz` — необязательная мировая ориентация. Без неё используется
  начальная ориентация, в том числе для будущих ключевых кадров.
- Между кадрами — квинтическая интерполяция позиции и SLERP ориентации
  с той же плавной временной функцией. В ключевых точках скорость нулевая.
- Один ключевой кадр означает удержание цели весь клип. После последнего ключа
  цель также удерживается до конца клипа.
- Времена начинаются с нуля и строго возрастают. При расширении цикла нужно
  увеличить `duration_s` и добавить ключи в соответствующие дорожки.
- `position_weight` и `orientation_weight` задают вес ошибки в IK;
  значение 0 отключает соответствующую составляющую.
- `phases` — только подписи для просмотра. Они не включают реальные захваты
  и не заменяют проверку контактов при будущем исполнении.

Для изменения движения достаточно отредактировать JSON и перезапустить просмотр.
Python-код для добавления стандартных дорожек кистей, стоп и корпуса менять не нужно.

## Сохранение результатов

```shell
python scripts/render/preview_ladder_reference.py --headless --render --video
```

Результаты по умолчанию в `outputs/ladder_reference_preview`:

- `reference_preview.npz` — время, решённые `qpos`, целевые позиции и ориентации,
  фактические позиции, ошибки, названия дорожек и исходный JSON;
- `validation.json` — максимальные ошибки и найденные проникновения геометрии;
- `frame_*.png` — изображения MuJoCo;
- `preview.mp4` — видео при `--video`.

Это промежуточный формат предпросмотра, не готовый датасет для training loader.
В нём сохраняются отдельно исходные цели и найденные позы, чтобы при дальнейшей
подготовке motion не потерять сведения о расхождениях.

## Границы проверки

IK соблюдает пределы суставов и проверяет кинематические ошибки. В отчёте
отмечаются проникновения глубже 2 мм вне опоры и глубже 5 мм для контактов
стоп с перекладинами. Проверяются отдельные кадры, не непрерывный swept volume.
Это не гарантирует отсутствие любых касаний и не подтверждает допустимость
скоростей, моментов приводов, распределения нагрузок или устойчивость в физике.

Геометрия лестницы, начальная поза и collision overlay вынесены в общие CPU-модули
`teleopit/runtime/ladder_scene.py` и `teleopit/runtime/g1_collision.py`.
Обучение использует те же определения. Исходная RL-задача сохранена;
отдельная задача обучения первой руки описана в [ladder_first_hand_training.md](ladder_first_hand_training.md).
