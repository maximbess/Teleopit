# Эталон переноса правой руки

Эталон строится из измеренной конечной позы первого переноса. Основная поза —
№48 из `outputs/first_hand_pose_bank`; левая кисть уже на перекладине №6,
правая ещё на №5. Индексы перекладин в NPZ/JSON начинаются с нуля: 5 и 4.

Параметры движения находятся в `assets/motions/ladder_second_hand.json`.
Начальные суставные углы берутся из банка, а цель правой кисти вычисляется
по смещению между реальными перекладинами. Сохраняется её исходное смещение
относительно перекладины, включая высоту над поверхностью и боковую координату.
Поза всего робота не зеркалится.

| Время, с | Этап |
|---|---|
| 0–0,5 | Удержание измеренной стартовой позы |
| 0,5–1,7 | Таз отходит на 2 см от лестницы; ориентация корпуса плавно приближается к нейтральной |
| 1,7–2,3 | Пауза для плавного отпускания правого захвата |
| 2,3–3,3 | Кисть отводится на 9 см от лестницы и на 6 см вправо |
| 3,3–5,9 | Подъём: на этой лестнице +28 см вверх и +10,5 см вперёд |
| 5,9–7,7 | Плавный подвод к новой перекладине с возвратом бокового отведения |
| 7,7–8,7 | Неподвижный суставной эталон для захвата и удержания |

Левая кисть и обе стопы сохраняют мировые положения и ориентации. Положение
таза и ориентация корпуса задаются отдельными треками. Позиция начала тела
torso не фиксируется независимо от таза: это создавало несовместимые ограничения
при повороте талии; её отклонение всё равно записывается в отчёт.
Между ключами используется квинтическая интерполяция и SLERP. Она задаёт
нулевые скорости и ускорения декартовых целей на границах сегментов.
Скорости суставного решения проверяются отдельно — IK не гарантирует C2-гладкость.

## Запуск

Нужны банк конечных поз (`manifest.json`, `scene.mjb`, `states/`) и Python
окружение проекта с MuJoCo; для MP4 — imageio/ffmpeg. `scene.mjb` был собран
MuJoCo 3.8.1. Банк и результаты находятся в ignored `outputs/`, в Git они не
входят. Для другого компьютера перенесите `outputs/first_hand_pose_bank.zip`
и распакуйте банк в тот же относительный каталог.

Из корня репозитория, в активированном окружении `teleopit`:

```bash
# Нативный просмотр MuJoCo, основная поза №48
python scripts/render/preview_second_hand_reference.py --paused

# Проверка всех восьми поз + MP4 основной позы
python scripts/render/preview_second_hand_reference.py --headless --all-representatives --video

# Другая стартовая поза
python scripts/render/preview_second_hand_reference.py --index 24 --paused
```

Управление: P — воспроизведение/пауза, J/L — кадры, R — сначала,
`[`/`]` — скорость, T — траектории, C — камера. Стартовая скорость просмотра 0,5×;
видеофайл воспроизводится в реальном масштабе времени.

На Windows при запуске Python по абсолютному пути, если окружение не активировано,
добавьте `<env>/Library/bin` в PATH и установите `MKL_THREADING_LAYER=SEQUENTIAL`.

## Результаты и формат

`outputs/second_hand_reference/pose_0048/` содержит:

- `reference.json`: конкретные мировые цели шести треков, стадии, намерения по
  контактам, происхождение исходной позы и её SHA-256;
- `reference.npz`: 436 отсчётов при 50 Гц, `qpos`, `qvel`, время, положения и
  ориентации целей, фактические положения и ошибки IK;
- `validation.json`: качество слежения, пересечения, ограничения суставов,
  численные оценки скорости/ускорения и ориентация корпуса при отпускании;
- `preview.mp4`: кинематическая визуализация с траекторией правой кисти.

`qpos` и `qvel` используют порядок MuJoCo для сохранённого MJB; карта задаётся
`joint_names`, `joint_qposadr`, `joint_dofadr`. Free joint занимает 7 элементов
qpos и 6 элементов qvel. Кватернионы имеют порядок wxyz. `qvel` вычислена
обратной разностью через `mj_differentiatePos`, поэтому корректно учитывает
кватернион свободного корпуса; это численная оценка скорости эталона.
`initial_measured_qvel` хранит исходную измеренную скорость отдельно.

Эталон начинается точно с измеренной qpos, но с нулевой целевой скоростью.
Будущий физический контроллер должен плавно погасить небольшую измеренную
скорость на стадии settle. На постоянных целях IK сохраняет последнюю позу,
чтобы избыточные суставы не продолжали смещаться во время удержания.
Усиленная регуляризация к предыдущему отсчёту ограничивает резкие изменения
суставной конфигурации. Значения по умолчанию первого эталона не изменены.

Проверены позы 48, 47, 12, 24, 25, 60, 18, 61. Для каждой эталон строится заново:
это проверка геометрического переноса, а не успешного исполнения одного
фиксированного клипа из восьми состояний.

Критерии: ошибка активных позиционных целей <5 мм, ориентаций <3°,
запас до суставных пределов ≥0,05 рад, скорость ≤2,5 рад/с, ускорение
≤20 рад/с², ориентация корпуса при начале отпускания <0,25 рад,
точное совпадение стартовой qpos. Выходной код 2 означает провал проверки.
Столкновения проверяются в отсчётах: учитываются проникновения >2 мм,
для ожидаемой опоры стоп на перекладины — >5 мм. Это не непрерывная проверка
всего промежутка и не оценка контактных сил.

## Ограничения и дальнейшее подключение

Это **кинематический эталон**, ещё не физически проверенный контроллер.
Визуализация задаёт qpos напрямую и отключает weld; расписание в JSON само
не отпускает и не включает захваты. Устойчивость после отпускания правой
кисти, допустимые моменты приводов и запас от проскальзывания пока не измерены.
Время удержания здесь означает длительность клипа, а не подтверждённый успех.

Следующий этап — физическое исполнение приводами из pose bank, с реальными
контактами и левым weld. Отпускание правой руки нужно разрешать по нагрузкам,
скоростям и состоянию опор; захват — подтверждать по положению и скорости кисти;
успех — по непрерывному устойчивому удержанию. При необходимости эталон
останавливается на границе стадии. Затем можно подключать residual policy.

У исходного банка `reference_signature_matches=false`: checkpoint обучался
с другой сигнатурой первого эталона. Здесь используются действительно
достигнутые локально и проверенные позы; это не точная реплика облачного rollout.
Обе сигнатуры сохраняются в provenance нового эталона.
